## Later in the session: usage numbers and a taskbar widget
The owner asked: "show ram, gpu and cpu usage for both" and "put the widget in the task bar".
- Inspected the taskbar: `Shell_TrayWnd` with a `TrayNotifyWnd` child that exactly covers the tray. Checked the counters: CPU `% Processor Utility`, about 585 `GPU Engine` instances, RAM.
- Prototyped a see-through child window in the taskbar. It failed ("The operation completed successfully" from `CreateWindowEx`) until the exe had a manifest declaring Windows 8–11 support. With that, it docked left of the tray, and `WindowFromPoint` confirmed clicks reach it (D14, D15).
- Built it into the app: `Stats` (PDH), `Link` (UDP 47815), `StatTile` / `WidgetRow` / `TaskbarDock`, tray menu Widget > In the taskbar / On the desktop / Hidden, plus "This PC is". The setup writes the manifest at build time.
- An AI-tool gotcha: the file-writing tool turned typed `\u2013`-style escapes into real characters. The patch script's ASCII check caught it, and the backslashes were rebuilt with `chr(92)`. The same thing had already broken two lines of this folder in the first commit; fixed now.
- First install on this PC said "this computer is 'Nvidia'", because the owner was on the Nvidia PC (the monitor showed input 15) while the setup ran. Added cable-type detection (`Identity`, `/whoami`): HDMI → AMD, even while the monitor shows the other PC (D18).
- Verified on this PC: the widget docks and shows live numbers; a fake Nvidia message shows on the Nvidia tile; desktop mode works; the app costs about 0.03% CPU; the owner allowed the firewall prompt.
- Updated the README and this folder.
